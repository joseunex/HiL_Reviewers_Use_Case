# HiL_Reviewers_Use_Case

Reproducibility package of the closed-loop batch-reactor use case of the paper *Integrating Hardware-in-the-Loop
into IoT Systems Simulations: A Model-Driven Development Approach* (use case 2, Section 7). It contains the code
generated by the SimulateIoT model-to-text transformations for the use case, the deployment and experiment scripts,
the files of the hardware-in-the-loop bench, the data of every run reported in the paper and the scripts that
regenerate its tables and figures.

## Layout

| Folder | Content |
|---|---|
| `sensthread1/`, `acta0/`, `foga0/`, `EsperComponentfoga0/` | Generated components: background sensors, actuator, Fog node and Esper-based CEP engine (Java, Maven, Dockerfiles). The CEP and the Fog node include the corrections made during the revision of the paper (no fixed sleep after each publication, release in global order of the source timestamp, per-second `ESPER_STATS` line). |
| `ClosedLoopSensor/` | The simulated thermal sensor of the reactor (the `UserDevice` of the paper), written for this use case: it computes the thermal model of Section 7.3 from the last applied actuator command. |
| `Testing/Packaging/` | Scripts that compile the Java components and build and push the Docker images (phases 1 to 3). |
| `DeployV2/k8s/` | Kubernetes manifests, `apply-all.sh` / `reset-all.sh`, `run_experiment.py` (deployment, data collection, optional CEP outage) and `analyze_experiment.py` (latency, fidelity, CEP and resource metrics of one run). |
| `hil_bench/` | Variant with physical devices used in the paper: Arduino Yún actuator sketch and its clock helper, scripts to join the Raspberry Pi to the cluster, NTP/chrony configuration, clock-offset measurement, multi-architecture image of the thermal sensor, and the campaign runner. |
| `data/` | Light data of the 57 runs of the paper (scalability, fault injection and sensitivity to the synchronization settings) and the aggregated CSV files. |
| `analysis/` | Scripts that summarise a campaign and regenerate Tables 4 to 6 and Figures 10 to 12 from `data/`. |

## How to use it

- To run the experiments without physical devices (every component as a container in a Kubernetes cluster):
  `EXPERIMENT_GUIDE.txt`.
- To run them on a HiL bench like the one of the paper (thermal sensor on a Raspberry Pi, actuator on an Arduino
  Yún): `hil_bench/README.md`.
- To look at the data of the paper or regenerate its tables and figures: `data/README.md`.

## Requirements

Kubernetes (tested with K3s), Docker, Maven and a JDK for the components; Python 3 with pandas, numpy and
matplotlib for the experiment and analysis scripts; arduino-cli and the Arduino libraries of the generator
(Bridge, PubSubClient 2.8 or later, TinkerKit) for the Yún sketch.
